# البحث الذكي في أرشيف أبو علي

[English](README.md) | [Nederlands](README.nl.md) | **العربية**

**بحث دلالي مدعوم بالذكاء الاصطناعي وإجابة عن الأسئلة (RAG) عبر أرشيف ضخم من
الفيديوهات العربية المفرَّغة نصياً — يعمل محلياً بالكامل، بتسريع GPU، مع نتائج
مفهرسة زمنياً وقابلة للتشغيل.**

هذا مشروع لتقصّي الحقائق: جعل كل تصريح علني لـ"معالج" مزعوم قابلاً للبحث، بحيث
يمكن مقارنة كلامه بعضه ببعض وبالواقع. انظر
[لماذا يوجد هذا المشروع](#1-لماذا-يوجد-هذا-المشروع).

الموقع المباشر: <https://aboali.scrib-r.com>

## 1. لماذا يوجد هذا المشروع

هذا مشروع لتقصّي الحقائق. موضوعه، **أبو علي الشيباني**، شخص يدّعي أنه وسيط
روحاني يتلقى رسائل وتعليمات من "معلّمه"، ويزعم قدرته على شفاء الناس من كل
الأمراض تقريباً — بأدوية خاصة يبيعها بآلاف اليوروهات لمشاهدين لا يشكّون في
شيء، عبر برنامجه التلفزيوني وموقعه وقناته على يوتيوب. وقد كان من بين ضحاياه
أشخاص أعزّاء عليّ.

الجدال معه أو مع أتباعه لا يجدي؛ وقد ثبت ذلك مراراً. لذلك يسلك هذا المشروع
طريقاً آخر: **دَع الرجل يكذّب نفسه بنفسه**. اجمع كل ما قاله وادّعاه يوماً، في
كل وسيط إعلامي، واجعله قابلاً للبحث لأي شخص. فعندما يمكن العثور على كل نبوءة
وادّعاء وتناقض في ثوانٍ — مع مقطع فيديو قابل للتشغيل ومختوم بالوقت كدليل —
لا يعود هناك حاجة للجدال.

الخطة، في ست خطوات:

1. العثور على كل ما قاله يوماً، في جميع صيغ الوسائط والمصادر.
2. تحويل جميع تصريحاته إلى نص رقمي.
3. بناء مكتبة بيانات تضم فيديوهاته وصوته وتفريغاته النصية.
4. جعل المكتبة قابلة للبحث بتقنيات الذكاء الاصطناعي (tokenization،
   vectorization، RAG).
5. بناء تطبيق على الإنترنت ليتمكن *أي شخص* من البحث في ادّعاءاته.
6. نشر كل شيء علناً، لتتحدث الحقائق عن نفسها.

هذا المستودع هو الخطوات 4–6: بوابة البحث فوق الأرشيف المفرَّغ نصياً. أما خط
التفريغ النصي الذي يغذّيه (الخطوتان 2–3) فقد تطوّر إلى منتج مستقل:
[scrib-r](https://www.scrib-r.com)، بوابة لتحويل الفيديو والصوت إلى نص
(مجانية ما دامت في مرحلة ألفا).

الطريقة نفسها تصلح لمحاسبة *أي* شخصية عامة على كلامها. إن كنت تعرف دجّالين
آخرين يستغلون الناس، فيسعدني المساعدة في التصدي لهم أيضاً.

## 2. ما هو التطبيق

يجعل هذا التطبيق أرشيف فيديو من نحو 2500 حلقة (2015–2026، حوالي 500 غيغابايت
من الوسائط مع تفريغات نصية مميَّزة بالمتحدثين) *قابلاً للبحث بالمعنى*. فبدلاً
من مطابقة الكلمات المفتاحية، يُضمَّن كل مقطع من التفريغ في فضاء متجهات متعدد
اللغات، بحيث يعثر سؤال بصياغتك الخاصة على اللحظات التي ناقش فيها المتحدث ذلك
الموضوع فعلاً — حتى لو اختلفت الألفاظ.

تُقدَّم طريقتا تفاعل عبر صفحة ويب عربية واحدة (من اليمين إلى اليسار):

| الوضع | ما يحدث |
|---|---|
| **🔍 بحث فقط** (بحث دلالي) | يُضمَّن الاستعلام على وحدة GPU ويُطابَق مع نحو 160,000 مقطع نصي. تظهر النتائج في جدول: **تاريخ** الحلقة، **التوقيت داخل الفيديو**، **النص المطابق** مظللاً، و**عنوان** الحلقة — مرتبة حسب الصلة وقابلة للتصفية حسب نطاق التاريخ. |
| **🤖 اسأل الذكاء الاصطناعي** (RAG) | تُسلَّم أفضل المقاطع المطابقة إلى **نموذج لغوي محلي** يكتب إجابة عربية موثَّقة بالمصادر تصف *ما قيل ومتى*. الاستشهادات مثل `[3]` في الإجابة تنقلك إلى صف المقطع المقابل. |

يوفر كل صف من النتائج طريقتين *لمشاهدة اللحظة بعينها*:

- **▶ تشغيل** — يشغّل ملف الوسائط المحلي في مشغّل داخل الصفحة، منتقلاً
  تلقائياً إلى نحو ثانيتين قبل المقطع المقتبس (يُبَث بدعم HTTP Range، فيكون
  التنقل داخل ملفات بحجم عدة غيغابايتات فورياً).
- **YouTube ↗** — رابط عميق بالشكل
  `https://www.youtube.com/watch?v=<id>&t=<seconds>s` يفتح اللحظة نفسها على
  الإنترنت؛ مناسب للمشاركة مع الآخرين.

كل شيء — التضمين، والاسترجاع، وتوليد الإجابة، وبث الوسائط — يعمل على الجهاز
المحلي. لا تُستخدم أي واجهات سحابية ولا تغادر أي بيانات المضيف.

## 3. البنية المعمارية

```
                       ┌──────────────────────────────────────────────┐
                       │  FastAPI app (uvicorn, port 8901)            │
 Browser (RTL SPA) ───▶│                                              │
   static/index.html   │  /api/search ──▶ BGE-M3 query embedding      │
                       │                  cosine top-k on GPU          │
                       │                  (~160k × 1024 fp16 matrix)   │
                       │                                              │
                       │  /api/ask ─────▶ retrieval (as above)        │
                       │                  → OpenAI-compatible local   │
                       │                    LLM (llama.cpp / Qwen3)   │
                       │                  → cited Arabic answer       │
                       │                                              │
                       │  /media/{file} ─▶ Range-enabled streaming    │
                       │                   of local mp4/m4a           │
                       └──────────────────────────────────────────────┘
                                        ▲
                     build_index.py (offline, one-time / on new videos)
                     parses transcripts → chunks → GPU embeddings
                     → index/index.sqlite + index/embeddings.npy
```

### تصميم الاسترجاع

- **التقطيع (Chunking)** — تُدمج المقاطع المتتالية للمتحدث نفسه حتى نحو 700
  حرف (`MERGE_TARGET_CHARS` في `build_index.py`) مع الحفاظ على توقيتات
  البداية/النهاية الأصلية. هكذا يحصل كل متجه على سياق كافٍ مع بقاء التوقيتات
  دقيقة. نحو 2500 فيديو ← نحو 160,000 مقطع.
- **التضمينات (Embeddings)** —
  [`BAAI/bge-m3`](https://huggingface.co/BAAI/bge-m3) (الوضع الكثيف،
  1024 بُعداً، fp16)، من أقوى نماذج الاسترجاع المفتوحة متعددة اللغات للعربية.
  يُحمَّل مباشرة عبر `transformers` (تجميع CLS + تسوية L2) — دون الحاجة إلى
  إطار عمل ثقيل.
- **البحث المتجهي** — عمداً *ليس* قاعدة بيانات متجهات. المصفوفة كاملة
  (160 ألفاً × 1024 fp16 ≈ 320 ميغابايت) تقيم على وحدة GPU، والاستعلام عملية
  ضرب مصفوفات واحدة: بضع ميلي ثوانٍ، نتائج دقيقة (بلا تقريب ANN)، وصفر بنية
  تحتية. يتوسع هذا بارتياح حتى ملايين المقاطع قبل أن تصبح FAISS/qdrant
  مجدية.
- **التصفية بالتاريخ** — يحمل كل مقطع تاريخ رفع حلقته؛ تُطبَّق المرشحات
  بإخفاء الدرجات قبل اختيار top-k.

### توليد الإجابة (RAG)

يبني `/api/ask` موجّهاً من مقتطفات مرقّمة (عنوان الحلقة، التاريخ، التوقيت،
النص) مع سؤال المستخدم، ويستدعي **أي نقطة نهاية محادثة متوافقة مع OpenAI**.
افتراضياً يكتشف تلقائياً حاوية llama.cpp باسم `scrib-r-backend-llama-1`
(Qwen3-8B) عبر `docker inspect`؛ ويمكن التجاوز بمتغيرات البيئة (انظر
الإعدادات). تُحذف كتل `<think>…</think>` الصادرة عن نماذج الاستدلال؛ وتُربط
علامات الاستشهاد `[n]` في الإجابة بجدول المصادر.

## 4. التقنيات

| الطبقة | التقنية | لماذا |
|---|---|---|
| التضمينات | `BAAI/bge-m3` عبر 🤗 `transformers`، PyTorch، CUDA fp16 | من أفضل نماذج الاسترجاع الكثيف المفتوحة متعددة اللغات (بما فيها العربية)؛ يعمل على V100 واحدة |
| البحث المتجهي | ضرب مصفوفات PyTorch على GPU | دقيق، بزمن استجابة ميلي ثانية على هذا الحجم، دون خدمة إضافية |
| مخزن البيانات الوصفية | SQLite | ملف واحد، تخزين بلا تشغيل وصيانة لبيانات الفيديوهات والمقاطع |
| الخلفية | FastAPI + uvicorn | واجهة Python غير متزامنة، تقديم ملفات ثابتة، `FileResponse` بدعم Range |
| نموذج الإجابة | أي خادم متوافق مع OpenAI (llama.cpp، LM Studio، Ollama، vLLM) | مستقل عن المزوّد؛ الافتراضي حاوية llama.cpp مع Qwen3-8B |
| الواجهة الأمامية | HTML/CSS/JS خام، RTL، تدعم الوضع الداكن، متجاوبة (عرض بطاقات للجوال) | بلا خطوة بناء، بلا إطار عمل — ملف واحد |
| النشر | خدمة systemd + وكيل عكسي nginx + Let's Encrypt (certbot) | استمرارية بعد إعادة التشغيل، TLS، اسم مضيف عام |

## 5. تنسيق البيانات المتوقع

يقرأ المفهرس مجلداً مسطحاً (افتراضياً `/data/ABO_ALI`) يحتوي، لكل فيديو:

```
<YYYYMMDD>_<youtube-id>.metadata.json   # العنوان، الرابط، تاريخ الرفع، المدة
<YYYYMMDD>_<youtube-id>.json            # التفريغ: segments[] تتضمن
                                        #   speaker_id, speaker, start, end, text
<YYYYMMDD>_<youtube-id>.mp4             # (أو .m4a) وسائط محلية، اختيارية
```

مثال على `metadata.json`:

```json
{
  "id": "MwBBTTMiS5s",
  "title": "…",
  "url": "https://www.youtube.com/watch?v=MwBBTTMiS5s",
  "upload_date": "20150110",
  "duration_seconds": 4131.0
}
```

التفريغات بهذا التنسيق يُنتجها خط WhisperX + pyannote
(مثل [scrib-r](https://github.com/sayfjawad/scrib-r))؛ ويصلح أي مصدر ما دام
شكل JSON مطابقاً.

## 6. التثبيت

### المتطلبات

- Linux، وPython 3.10 أو أحدث
- وحدة NVIDIA GPU بذاكرة ≥ 8 غيغابايت VRAM (المُختبَر: Tesla V100 32 GB) +
  نسخة PyTorch بدعم CUDA
- نحو 500 ميغابايت مساحة تخزين للفهرس (عند 160 ألف مقطع)
- اختياري: خادم LLM متوافق مع OpenAI لوضع "اسأل الذكاء الاصطناعي"
- اختياري: Docker (فقط للاكتشاف التلقائي لحاوية llama.cpp الافتراضية)

### إرشادات العتاد للخط الكامل

هل تريد بناء أرشيف كهذا بنفسك، من البداية إلى النهاية؟ إرشادات تقريبية من
واقع هذا المشروع:

**المكتبة القابلة للبحث + النموذج المحلي (هذا المستودع):**

- وحدة GPU بذاكرة لا تقل عن 16 غيغابايت VRAM — تعمل 24 غيغابايت جيداً،
  و32 غيغابايت (مثل RTX 5090) مثالية لتشغيل نموذج التضمين ونموذج الإجابة
  معاً بارتياح
- معالج من جيل حديث (i5 / Ryzen 5 أو أحدث)
- اتصال بالإنترنت لاستضافة الموقع

**التفريغ النصي (المرحلة السابقة، مثل [scrib-r](https://github.com/sayfjawad/scrib-r)):**

- وحدة GPU بذاكرة 8 غيغابايت VRAM و16 غيغابايت RAM
- معالج حديث (يُنصح بـ i5 / Ryzen 5 أو أعلى)
- مساحة SSD كافية للوسائط التي تجمعها — يستخدم هذا الأرشيف نحو 500 غيغابايت

بهذا التجهيز — وبمساعدة ذكاء اصطناعي عبر الإنترنت عند الحاجة — يمكنك وضع أي
شخصية عامة مريبة تحت المجهر.

### التثبيت

```bash
git clone git@github.com:sayfjawad/abo-ali-search.git
cd abo-ali-search
python3 -m venv --system-site-packages .venv   # لإعادة استخدام torch بنسخة CUDA من النظام إن وُجدت
.venv/bin/pip install "fastapi>=0.110" "uvicorn[standard]>=0.29" transformers torch numpy httpx
```

> إذا كان Python في نظامك يوفر أصلاً نسخة CUDA من `torch` (كما في مضيفات
> تعلم الآلة)، فإن `--system-site-packages` يجنّبك تثبيتاً ثانياً بعدة
> غيغابايتات. على جهاز نظيف، احذف هذا الخيار ودع pip يثبّت torch.

### بناء الفهرس

```bash
# عدّل DATA_DIR في build_index.py إذا كان أرشيفك في مكان آخر
CUDA_VISIBLE_DEVICES=0 .venv/bin/python build_index.py
```

يُنزّل التشغيل الأول نموذج BGE-M3 (نحو 2.3 غيغابايت) إلى `HF_HOME`. تستغرق
فهرسة كامل الأرشيف المكوّن من 2500 فيديو نحو 8 دقائق على V100. أعد التشغيل
كلما أُضيفت فيديوهات جديدة (يُعاد بناء الفهرس من الصفر؛ وهي عملية رخيصة).

### التشغيل

```bash
./run.sh                # http://localhost:8901
```

### التشغيل كخدمة (systemd)

```bash
sudo cp deploy/aboali-search.service /etc/systemd/system/
# عدّل User/WorkingDirectory/المسارات إن اختلفت
sudo systemctl daemon-reload
sudo systemctl enable --now aboali-search
```

### HTTPS عام عبر nginx + certbot (اختياري)

على المضيف المواجه للإنترنت (قد يكون جهازاً آخر يصل إلى التطبيق عبر شبكة
VPN/overlay):

```bash
sudo cp deploy/nginx-aboali.conf /etc/nginx/sites-available/aboali.example.com
# عدّل server_name وهدف proxy_pass
sudo ln -s /etc/nginx/sites-available/aboali.example.com /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d aboali.example.com --redirect
```

`proxy_buffering off` والمهل الطويلة في الإعداد المرفق مهمة لسلاسة بث
الفيديو عبر الوكيل.

> ⚠️ التطبيق نفسه **بلا مصادقة**. إذا عُرض علناً، يمكن لأي شخص البحث وبث
> ملفات الوسائط واستخدام نقطة "اسأل الذكاء الاصطناعي" (المستهلكة لموارد
> GPU). احمِه بـ nginx basic-auth أو قائمة سماح أو وكيل مصادقة عند الحاجة.

## 7. الإعدادات

كلها اختيارية، عبر متغيرات البيئة (انظر `run.sh` / وحدة systemd):

| المتغير | الافتراضي | الغرض |
|---|---|---|
| `HF_HOME` | `/data/huggingface` | موقع ذاكرة التخزين المؤقت لنماذج Hugging Face |
| `CUDA_VISIBLE_DEVICES` | `0` | أي GPU يضمّن الاستعلامات / يحمل المصفوفة |
| `LLM_BASE_URL` | اكتشاف تلقائي لحاوية `scrib-r-backend-llama-1` | نقطة نهاية متوافقة مع OpenAI لوضع اسأل الذكاء الاصطناعي، مثل `http://localhost:1234/v1` |
| `LLM_MODEL_ID` | `qwen3-8b` | اسم النموذج المُمرَّر إلى نقطة النهاية |
| `LLM_API_KEY` | `none` | رمز Bearer إذا تطلّبته نقطة النهاية |

مسارات موجودة في الشيفرة: مجلد الأرشيف (`DATA_DIR` في `build_index.py`،
`MEDIA_DIR` في `app.py`) وحجم دمج المقاطع (`MERGE_TARGET_CHARS`).

## 8. واجهة HTTP

| نقطة النهاية | الطريقة | الجسم / المعاملات | تُرجع |
|---|---|---|---|
| `/api/search` | POST | `{query, top_k?, date_from?, date_to?}` (التواريخ `YYYYMMDD`) | `{results: [{score, video, title, date, start, end, start_fmt, text, youtube_url, media_url, …}]}` |
| `/api/ask` | POST | `{question, top_k?, date_from?, date_to?}` | `{answer, error, sources: [...]}` — تحمل المصادر `cited: true` حيث استُشهد بها |
| `/api/stats` | GET | — | `{videos, chunks}` |
| `/media/{file}` | GET | يدعم Range | بث mp4/m4a |
| `/` | GET | — | واجهة الصفحة الواحدة |

مثال:

```bash
curl -s localhost:8901/api/search -H 'Content-Type: application/json' \
  -d '{"query":"ماذا قال عن الزلازل في تركيا","top_k":5,"date_from":"20160101"}'
```
